# 编舞改进方案

> 状态：**P1 + P2 已完成**（2026-11-08），下一步 P3/P5 或脚部 IK。写于 C1/B3 之后。
> 目标：让 3 分半的表演在**不看歌词**的情况下也像在跳舞，而不是「同一个小动作循环 + 偶尔换手」。
>
> **2026-11-10 更新**：P1/P2 之后用户反馈「动作还是抽象，除了转圈/点头/摇头，
> 其它一言难尽」。诊断和 v2 方案见第 7 节——**结论是 P3/P4/P6 的顺序要改**：
> 先做「姿势库 + 关键帧 + 脚 IK」，因为现在这套 clip 描述的是**运动**，
> 而观众记住的是**姿势**。

---

## 1. 现状（实测，不是感觉）

| 指标 | 数值 |
|---|---|
| 可调度动作 | 6 个（bounce / spin / wave / peace / nod / shake） |
| 指令数 | 69 条 / 204.6s |
| `dance.bounce` 覆盖时长 | **109.2s（53%）**，分 10 段 |
| 每 30s 窗口出现的动作种类 | 4–6 个，**而且每个窗口基本一样** |

各窗口的动作集合：

```
  0- 30s  bounce spin wave nod shake peace
 30- 60s  bounce spin wave      peace
 60- 90s  bounce spin wave nod       peace
 90-120s  bounce      wave nod shake
120-150s  bounce spin wave      peace
150-180s  bounce spin wave      shake peace
180-210s  bounce spin       nod       peace
```

**问题不是「动作太少」，而是「同一时刻只有一个动作，而且这个动作本身幅度很小」。**

---

## 2. 为什么看起来单调

### 2.1 主力律动本身太「温」

`dance.bounce` 占了 53% 的时间，它的全部幅度是：

| 部位 | 幅度 |
|---|---|
| 上臂 | `0.34 rad` ≈ 19°（还是平举方向，不贴身） |
| 膝盖 | `0.62 rad`（屈伸） |
| 髋部旋转 | `0.05 rad` ≈ 3° |
| 左右重心 | **没有**（hips 的位移只有上下 `-0.055`） |

所以一半时间的画面是「原地小幅屈膝、手臂向外张开一点点」。这是最主要的原因。

### 2.2 叠加会被平均稀释

`ParamBus` 对**同一根骨骼**是加权平均：

```
pose.bone = (Σ v_i · w_i) / (Σ w_i)
```

`dance.bounce`（base 层）和 `dance.wave`（upper 层）**都写 `chest` 和 `head`**。
两个都开的时候，这两根骨骼各取一半 —— 弹跳的点头幅度减半，挥手的倾身也减半。

**结果是「动作越多越平」**，这是当前架构里最反直觉的一点。

### 2.3 时间上永远只有「一个姿态」

`base` / `upper` 是互斥层，叠加又会被 2.2 稀释。所以一屏最多两个 clip，
而且互相削弱。没有「下半身一直在动 + 上半身做别的事」这种真正的分层。

### 2.4 乐句之间是独立随机

每个 5 秒乐句各自抽一次动作，乐句之间没有关系：没有动机重复、没有 A/B 段落、
没有预备拍、没有留白。听感上像抽卡，不像编舞。

## 3. 方案

按性价比排序，每一步都能单独验收。

### P1. 重写主力律动 —— 已完成（2026-11-08）

**做了什么**：把 `dance.bounce` 从「屈膝 + 张手」改成真正的左右重心摇摆。

- 髋部左右位移 ±0.055 + 侧倾 0.125 rad + 微转 0.11 rad
- 重心每 2 拍（快歌 4 拍）切换一次，**相位和屈伸对齐**：重心到边的那一拍正好是身体最低的那一拍
- 肩胸与髋**反相**，上身滞后 0.18 拍，形成「腰先动、肩跟上」
- 承重腿伸直、另一条腿屈（膝角 0.26 vs 0.74 rad），脚踝跟着翻
- 手臂贴身带肘弯，左右幅度差 0.08 rad，避免完全对称的机器人感
- 快歌自动改成两拍一沉（>130 BPM），否则一拍一沉会抖成筛子

**顺带改了生成器**（这一条收益比 clip 本身还大）：

`build_choreo.py` 在 `mid` 档位以前是 `stop_bounce()` 再排手势，结果主歌整段
身体是静止的。现在中段保留律动，手势走 `upper` 层叠上去。

| 曲包 | 基础层覆盖（前 → 后） | 最长空档（前 → 后） | 上下层同时存在的时长 |
|---|---|---|---|
| demo | 55.9% → **83.8%** | 22.9s → **15.9s** | 54.5s |
| 白花 | 82.9% → **88.2%** | 32.7s → **21.8s** | 69.5s |
| 剣花 | 46.7% → **67.2%** | 48.5s → **27.7s** | 27.0s |

（`tools/measure_choreo.py` 是这次为量这个写的。）

**验收**：`?freeze=dance.bounce&beat=0|1|2` 抽三帧，重心方向一眼可辨。
截图 `shots/groove/groove-strip.png`。

**还剩下的**：`calm` 段（前奏/间奏）仍然完全不跳，这是有意的留白；但如果想更满，
需要一个幅度收敛版的律动（P3 的 `amp` 变体）。

**已知缺陷：脚会「离地」**（用户 2026-11-08 反馈）。原因是**没有 IK**：

- 髋部平移（`hipsOffset.x`）会把整条腿一起搬走 → 脚横向滑动；
- 髋部侧倾（`hips.roll`）会让两条腿跟着倒 → 一只脚抬起来、另一只穿进地面；
- 屈膝让脚踝前进并抬高，而 `hipsOffset.y` 又同时下沉，两层叠加后脚不贴地。

已做的**部分缓解**：腿的 z 旋转抵消掉髋部侧倾（`-0.095 * sway`，髋是 `0.125`），
骨盆歪、腿保持竖直，这是现实中重心转移的样子；剩下的是横向滑动和屈膝抬脚。

**真正的修法是脚部 IK**：给定两只脚的落点（世界坐标固定），反解脚踝/膝关节。
两天左右，而且要先有 P2 的骨骼所有权（否则 IK 的解会被别的 clip 平均掉）。
在那之前不动 P1 的幅度。


### P2. 骨骼所有权 —— 已完成（2026-11-08）

**做了什么**：`ActionClip` 多了两个字段 `owns?: BoneName[]` / `ownsHips?: boolean`，
`ParamBus` 的合成规则从「所有贡献加权平均」改成：

1. 没声明所有权的贡献照旧加权平均（老 clip 不改也能跑）；
2. 有 clip 声明拥有这根骨骼时，**优先级最高的拥有者独占**：
   `拥有者值 × 权重 + 平均其他贡献 × (1 - 权重)`；
3. 没有竞争者时直接给满值，所以淡入行为和以前一致。

各 clip 的划分：

| clip | 拥有 |
|---|---|
| `dance.bounce` | hips / spine / 双腿双脚（+ hipsOffset） |
| `dance.spin` | hips / 双臂（+ hipsOffset），优先级 70 压过律动的 50 |
| `dance.wave` | 右肩臂手 / chest / head |
| `pose.peace` | 右手整条链（含手指）/ chest / head |
| `gesture.nod` / `shake` | head / neck |

**验收（`tools/` 外的断言脚本 `.tmp/probe_p2.cjs`，用真实 ParamBus + 真实 clip）**：

```
膝盖（bounce 独占，wave 不写）
  只有 bounce      0.260000
  bounce + wave    0.260000      差值 0.00000000
胸（wave 独占）
  只有 bounce      0.030000
  bounce + wave    0.000000      wave 自己的值 0.000000
```

**副作用（有意为之）**：手势独占 `chest`/`head` 的那 1.6–2.2 秒里，律动的点头会被接管。
这是「上层覆盖」的本意，但如果以后觉得头太死，把 `head` 从手势的 owns 里拿掉即可。

### P3. 参数化 + 镜像（0.5 天）

**做什么**：动作不是硬编码的 6 个 ID，而是「基础动作 × 变体」。

- `side`：左 / 右（镜像）
- `amp`：0.6 / 1.0（收敛 / 放开）
- `speed`：半速 / 原速

**算术**：3 种律动 × 8 种手势 × 2 镜像 × 2 幅度 = **96 种姿态组**，
而 clip 仍然只写 11 个。这比「堆 20 个 clip」划算得多。
**验收**：副歌里同一句的两次出现，一次镜像、一次换幅度。

### P4. 乐句语法（2 天）

**做什么**：在「乐句 → cue」之间加一层模板。

- 4 小节 = 一句，句子有 A / B 两种
- 副歌用 `A A' B A''`（`A'` = 镜像，`A''` = 加幅度）
- **预备拍**：重拍动作提前 1/8 拍起手，命中重拍（现在所有动作都是「啪」地开始）
- **留白**：每 4 句留一句基本不动，密度才有对比

**为什么有效**：重复产生「这是编好的」的感觉，随机产生「这是随机的」的感觉。
**验收**：同一段落的两遍副歌能听出呼应。

### P5. 表情与视线参与（1 天）

**做什么**：

- 动作 clip 里带 `expression`（happy / surprised / relaxed）
- 动作期间**降低鼠标视线的权重**（现在鼠标完全接管头部，动作里的头部动作会被视线抵消）

**为什么有效**：桌宠的「在场感」很大程度来自眼睛和表情，不只是四肢。
**验收**：动作期角色的头跟着动作走，而不是一直追光标。

### P6. 动作库扩容（按需，每个 0.5 天）

候选（按编排价值排序）：举单手左右摆、指人、捂脸、后仰、半蹲、拍手、180° 转身、
双手上下打拍、歪头、耸肩。目标 15–20 个可调度 clip。

**注意**：动作越多越容易踩「`interrupt: 'none'` 静默吃掉下一个动作」的坑
（见 `tools/README.md`）。扩容前应该先让 `TrackPlayer.onPlay` 检查
`ParamBus.play()` 的返回值并打日志，否则又是「不报错、就是不动」。

## 4. 和 B1/B2 的关系

编舞生成器是流水线的一步，所以有两个硬约束，**现在就已经满足**：

1. **纯函数**：同样的输入 + 同 seed → 同样的 `actions.json`
2. **无交互**：`--pack` + `--audio` + `--out`，不读全局状态

B1 的 `job.json` 五阶段里它是第 4 步（separate → asr → align → units → choreo），
失败可以单独重跑。

**P3 的参数化会改变 cue 的 ID 写法**（如 `dance.wave.left`），
这是 `actions.json` 的格式变化——做 P3 的时候要顺手把 schema 版本号加上，
否则以后改一次格式就得猜是哪个版本的曲包。

---

## 5. 建议顺序

```
P1 律动重写
  └→ P2 骨骼所有权（先修稀释，否则 P3 的叠加没意义）
       └→ P3 参数化镜像
            └→ P4 乐句语法
                 └→ P5 表情视线
                      └→ P6 扩容
```

P1 单独做就能看到明显变化，可以先做 P1 再决定后面几个的优先级。

---

## 6. 明确不做

- **真实舞蹈动作库**（真人动捕 BVH 之类）：体积、授权、和 VRM 骨骼对齐都是大工程，
  与「桌宠」的定位不匹配。
- **逐帧物理（惯性、裙摆）**：视觉收益低于 P1–P4，先不做。
- **机器学习编舞**：没有数据，训练成本远超收益。

## 7. v2 方案：从「运动曲线」改成「姿势 + 关键帧」（2026-11-10）

> **进度（2026-11-10）**：**P7 姿势库 + P8 关键帧 已完成**。
> 30 个姿势（含镜像共 46 个）、6 个动作全部改成关键帧、出图见
> `shots/poses/sheet.png` 和 `shots/clips/strips.png`。下面是原计划，实现细节见 7.6。

用户的判断是「转圈、点头、摇头算中规中矩，其它一言难尽」。这句话本身是诊断线索：
**转圈和点头是「有一个明确的姿势变化」，而律动/挥手/比耶是「一直在动但没有姿势」。**

### 7.1 五个可归因的原因（不是感觉）

| # | 现象 | 代码里的事实 |
|---|---|---|
| A | 像在滑冰 | `vrmRig.apply()` 写的是 `hips.position = rest + hipsOffset`，腿是 hips 的子节点。髋横移 55 mm，**两只脚跟着横移 55 mm**；`dance.spin` 把 hips 绕 Y 转满 `TAU`，脚跟着原地转 360°——真人要靠两步才能转身 |
| B | 没有「劲」 | 每个 clip 都是 `Math.sin(TAU * t / 周期)`。正弦没有「起手→到位→停住」，而动画里一个动作的辨识度**全在这三段**（击 0.08–0.12 s 到位） |
| C | 手臂像棍子 | `dance.wave` 只写 `rightUpperArm.z`，`rightShoulder` 给 0.22 的常量、肘部只做正弦。真人挥手是 肩胛→上臂→肘→腕 的**相位链**，现在四个关节同相 |
| D | 左右完全对称 | `dance.bounce` 左右只差 0.08 rad（19° 的幅度里），人跳舞左右差一般 20–30% |
| E | 记不住 | 6 个 clip 描述的都是「运动」，没有「造型」。观众记住的是手叉腰、指人这种**静态姿势**，不是轨迹 |

A 是硬缺陷（P1 里已经写过「脚会离地」），B/C/E 是表达问题。分开修。

### 7.2 四件套

#### P7. 姿势库（0.5 天）—— 作者不再写代码

新增 `src/actions/poses.json`（打包进 bundle，不是用户数据）：

```json
{
  "id": "arm.hip",
  "tags": ["arm", "stance"],
  "bones": { "rightShoulder": [0, 0, -0.08], "rightUpperArm": [0.25, 0, 0.62], "rightLowerArm": [0, 0, -1.35] },
  "hips": [0, -0.01, 0],
  "face": { "happy": 0.15 }
}
```

- 只写单侧。`mirrorPose()` 把 `left*/right*` 换名、x 取反，自动生成 `arm.hip.left`。
- 姿势 = 骨骼欧拉角，和现有 `ParamBus` 同构，**不需要改合成器**。
- 目标 20 个：`idle.base` / `idle.weight.L` / `idle.weight.R` / `arm.hip` / `arm.cross` /
  `arm.open` / `arm.up.L` / `arm.reach` / `hand.point` / `hand.peace` / `hand.heart` /
  `head.tilt` / `head.down` / `head.up` / `shrug` / `stretch` / `lean.back` / `crouch` /
  `step.L` / `step.R`。
- **验收工具**：把 `?freeze=` 扩成 `?pose=<id>&view=front`，一次渲染 20 张 380×520 拼成
  contact sheet 存 `shots/poses/sheet.png`。姿势表人和用户都能看，也是以后 LLM 动作
  （D4）的词汇表。

#### P8. clip = 关键帧序列（1 天）

`ActionClip` 加一种 `keys` 形态（老的 `sample` 保留，不破坏现有 clip）：

```ts
{
  id: 'gesture.wave.hand', layer: 'upper', priority: 60, owns: [...],
  keys: [
    { pose: 'arm.up.half',   at: 0.00, ease: 'inOut' },  // 起手
    { pose: 'arm.up.full',   at: 0.10, ease: 'out'   },  // 击：0.10 s 到位
    { pose: 'arm.up.full',   at: 0.18 },                 // 停一拍
    { pose: 'arm.wave.right', at: 0.38, ease: 'inOut' }, // 摆
    { pose: 'arm.wave.left',  at: 0.58, ease: 'inOut' },
    { pose: 'arm.up.full',   at: 0.78 },
    { pose: 'idle.base',     at: 1.20, ease: 'in' },     // 回落
  ],
}
```

要点：

- `ease`：`linear / in / out / inOut / back`（`back` 带过冲，是「落地感」的来源）。
- 关键帧之间在**欧拉角空间**线性插值——和 `ParamBus` 的加性/独占规则一致，
  不用改合成器，也不用碰四元数。
- 时间参数本身就是节奏：0.08–0.15 s = 击，0.3–0.5 s = 够得着，>1 s = 缓慢。
  **这是现在完全没有的一层**，也是「抽象」的最大来源。
- 一层里可以有多个 clip：下半身的关键帧只写腿，上半身的关键帧只写手臂，
  靠 P2 的 `owns` 保证互不稀释。

#### P9. 脚部 IK + 落脚点（1.5 天）

> **2026-11-10 用户修正**：我原来写的「支撑脚锁死、脚不离地」太死了。
> 转圈本来就该是「一只脚踮起、一只脚踩地」，脚**可以**离地。
> 正确的约束是**接触点不能滑**，不是「两只脚都钉在地上」。

每只脚一个状态机，逐帧取其中一个：

| 状态 | 约束 | 用在哪 |
|---|---|---|
| `plant` | 脚跟 + 脚掌贴地，位置和朝向都锁死 | 站立、重心左右转移 |
| `pivot` | **脚掌球部一个点固定**，脚绕竖直轴可以转、脚跟可以抬起 | 转身、踮脚 |
| `swing` | 离地，走一条弧线（抬起 → 落下） | 迈步、并步 |

- 「踮脚」是 `pivot` 的特例：接触点从脚掌中心移到脚掌球部，脚绕 X 轴转，
  髋部同时抬高 —— 不需要新机制。
- 只要有**一只脚**处于 `plant` 或 `pivot` 就不会飘；两只脚都在 `swing` 只在跳跃时允许。
- 转圈因此变成：支撑脚 `pivot` + 摆动脚收到支撑脚旁边，而不是整个人在地上转。

实现：两条腿各做 2 骨 IK（`upperLeg → lowerLeg → foot`），目标是脚踝的世界坐标：

1. 每帧算 hips 的世界位置 → 目标脚踝 = clip 给的接触点（`plant` / `pivot`）或路径点（`swing`）。
2. 用余弦定理解膝盖角，按 `1 ± 0.35*sway` 分配到承重/非承重腿。
3. 支撑脚在整段 clip 内位置和朝向锁死（`pivot` 时只锁接触点）。

修掉的东西：

- 髋横移不再拖脚（A）；
- 现在 3 处硬编码补偿（`-0.095 * sway` 等）可以删掉；
- 转身不再靠「髋部整体转 2π」。

成本在这里主要不是数学（2 骨 IK 二十行），是**把 FK 结果喂回归一化骨骼**：
`vrmRig` 现在直接写 normalized bone 的 rotation，IK 要写的是「世界空间的目标」，
得用 VRM 的 normalized→raw 关系反推，接缝处容易歪，要留一天调。
量验收指标用 `rig.getBoneWorldPosition()`：贴着地面走一圈，看支撑脚的位移 mm/s。

#### P10. 二次运动（0.5 天）

- 脊椎三段延迟链：`hips` → `spine`(40 ms) → `chest`(80 ms)；
- 肘/腕滞后 60 ms（就是 C）；
- 视线权重从 1.0 降到 0.35（P5 的内容，并到这里做）：动作期间头跟着动作走，
  不动的间隙才回来看光标。

#### P11. 扩容 + 乐句语法（2 天）

- 动作数 6 → 18（P6 的候选 + `step.touch`、`sway.arms`、`clap`、`turn.180`）；
- 把 P4 的乐句语法补上：4 小节一句、`A A' B A''`、重拍前 1/8 拍起手、每 4 句留一句基本不动；
- `build_choreo.py` 的 cue 从「每两小节抽一个 ID」变成「抽一个姿势序列」。

### 7.3 验收指标（都是可算的，不靠眼睛）

| 指标 | 现在（估） | 目标 | 怎么测 |
|---|---|---|---|
| 支撑脚世界坐标滑移 | 髋横移 55 mm/半拍 → **>30 mm/s** | **< 5 mm/s** | 逐帧取 `foot` 世界坐标，支撑期内算位移/时长 |
| 动作上升时间 | 正弦 → 无限长 | 0.08–0.15 s | 关键关节点从静止到峰值的 10%→90% 时间 |
| 10 s 窗口独立姿势数 | 1–2 | **≥ 3** | 姿态向量（20 维关节角）聚类 |
| 左右肢相关系数 | ~0.99 | **< 0.85** | 左右臂关节角时间序列的 Pearson |
| 4 s 姿势重复率 | — | **< 30%** | 姿态向量在 4 s 窗内的最近邻距离 |

前两项能直接证明 A 和 B 被修掉了；后三项对应 D/E。

### 7.4 顺序和成本

```
P7 姿势库 + 截图       0.5 天  → 有了词汇才谈得上排版
  └→ P8 关键帧         1.0 天  → 把现有 6 个 clip 全部改写成关键帧
       └→ P9 脚 IK     1.5 天  → 修滑步，让转圈成立
            └→ P10 二次运动 + 视线  0.5 天
                 └→ P11 扩容 + 乐句  2.0 天
```

**P7+P8 就能看到最大变化**（0–1.5 天），因为它同时修了 B/C/E；P9 修 A 但风险最高
（接缝），所以放第三。如果 P8 之后效果已经够，P9 可以只做「髋横移时锁脚」这一半。

### 7.5 明确不做

- 不做 mocap / BVH 动作库（体积、授权、重定向）；
- 不做物理（裙摆、惯性骨）——VRM 的 springbone 已经在做；
- 不做「大跳、下腰」这类大动作：桌宠窗口只有 380×520，大动作会出画，
  而且和「陪着你」的定位不符。**目标是把小动作做准，不是做大。**

### 7.6 实现记录（P7 + P8，2026-11-10）

**落地形态**（和上面设想的两处偏差）：

| 设想 | 实际 | 原因 |
|---|---|---|
| `poses.json` 数据文件 | `src/actions/poses.ts` | 打包进 bundle 不用配资源，而且有类型；JSON 还得写 loader 和 schema 校验 |
| `ActionClip` 加一种 `keys` 形态 | `createKeyframeClip(spec)` 编译成普通的 `sample()` | 合成器一行没改，老 clip / 调试 clip 全部兼容 |

**姿势库**：30 个作者写的姿势 + `.L` 自动镜像 = 46 个；`sym()` 合并左右对称的姿势
（手写两遍必然出现「两边差 0.05 rad」）。`?pose=<id>` 钉住任意姿势，
`node .tmp/pose_shot.mjs` + `.tmp/pose_sheet.py` 出对照表。

**关键帧**：`keys: [{ pose, at, ease }]`，`ease ∈ linear/in/out/inOut/back`，
`ease` 属于**这一段起点**。段间在两个姿势的骨骼并集上插值。
`loopBeats` 让律动按拍循环（`at` 的单位变成「拍」）。
`owns` 不写时自动取「所有帧出现过的骨骼」，避免被别的层平均稀释。

**六个 clip 的改法**：

| clip | 结构 |
|---|---|
| `dance.bounce` | 4 拍循环：重心左 → 沉 → 重心右 → 沉 |
| `dance.wave` | 预备 → 起手 → 击(0.1 s) → 摆两下 → 回落 |
| `dance.spin` | 预备蹲 → 90° → 180° → 270° → 360°（**结束在 2π 的姿势上**） |
| `pose.peace` | 手先到位，**手指晚 0.12 s** + `back` 过冲 |
| `gesture.nod` | 抬头预备 → 点头 → 抬头 → 再点 → 回正 |
| `gesture.shake` | 左 → 右 → 左（偏航），两头慢中间快 |

**踩到的三个坑（都记在代码注释里）**：

1. **手臂的「向前摆」是 y 轴，不是 x**。x 是绕上臂自身的拧转（会让掌心朝上），
   z 是冠状面里的抬放。第一版按 x 写，「合掌」「抱胸」全变成了举手欢呼。
   现在三个轴的含义写在 `poses.ts` 头部，姿势数值用 `.tmp/pose_probe2.mjs` 量：
   在一页里扫栅格、读手的实际世界坐标、选最接近目标点的那组。
   `clap` 的手位误差 **2.8 cm**。
2. **`const` 箭头函数踩 TDZ**：`sym()` 在模块初始化时就调用 `mirrorPose()`，
   而 `swapSide` 原来是 `const` 箭头，那时还在 TDZ 里 → 整个 bundle 启动即报错，
   表现是「模型一直载不进来」。改成函数声明。
3. **`ParamBus.play()` 同 id 只重置时间、不换 clip 内容**。姿势标定时反复
   `play({id:'debug.pose', ...})`，结果手的位置一直不变——因为跑的还是第一个 clip。
   现在调试钩子每次用新 id。这个语义本身没错（time 轴复用），但很容易踩。

**验证产物**：

- `shots/poses/sheet.png`：30 格姿势表（`?pose=` 逐格截图）
- `shots/clips/strips.png`：五个动作的关键帧胶片（`?freeze=<clip>&t=<秒>`）

**`pose.sing`（2026-11-10，用户点的第一个「描述出来的动作」）**：
一手前伸掌心向上、一手抚胸。两只手的位置是量出来的——注意前伸手是**斜 45°**的
（往前 31 cm、往外 32 cm），因为正对镜头时纯前伸会被透视压成短胳膊。
作者流程见 `docs/pose-authoring.md`。

**首尾一致规则（用户提议，已做成机械检查）**：一次性 clip 的第一帧和最后一帧
必须是同一个姿势，否则接在别的动作后面会在边界上跳一下。
`createKeyframeClip` 现在会比对首尾（骨骼 / 髋位移 / 表情，容差 1e-3）并 `console.warn`。
只有一个例外：转圈结束在偏航 2π 的姿势上（视觉等于首帧、数值不等于，
这样它才不会在淡出时倒着转回去），用 `skipPoseCheck: true` 显式豁免。

**还没修**：转圈时脚仍然跟着髋转（滑步），要等 P9 的脚部 IK。
