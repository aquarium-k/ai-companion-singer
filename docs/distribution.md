# 发布与轻量化（提案）

> 2026-11-18。三件事：**卖点怎么讲、发到哪、怎么瘦**。都只是提案，标了成本和取舍。

## 一、现在的体积，先看清钱花在哪

| 项 | 体积 | 能不能砍 |
|---|---|---|
| Electron 运行时（exe + dll + pak） | **~180 MB** | 换 Tauri 可砍到 ~10 MB（见四） |
| `app.asar` | **21 MB** | 其中 `node_modules`（three + three-vrm）约 12 MB、`dist` 5.2 MB、和声采样约 3 MB |
| `resources/models/saki.vrm` | **14 MB** | 已授权（VRM meta 允许分发），保留；可以出“不带模型”的瘦包让用户自己挑 |
| 打包后合计（免安装目录） | **264.7 MB** | 实测值（只留三套 locale 之后） |
| NSIS 安装包 | **89.6 MB** | 实测值（`compression: maximum`） |
| **不**进包的（原本 2.9 GB） | `.pylibs` 276 MB + `.svclibs` 1.2 GB + 模型 1.4 GB + HF 缓存 1.1 GB | 只给“要自己做曲包的人”单独下 |

**关键取舍**：导入歌曲的能力（分离/对齐/SVC）是三 GB 级的 Python 生态。
把它从安装包里拿掉，安装包就从 3 GB 级降到 300 MB 级 —— 这是最大的一刀，已经做了。

## 二、卖点怎么讲

按“别人没有 / 我们有”排：

| 卖点 | 依据 | 怎么讲 |
|---|---|---|
| **她真的在唱和声**（不是播放录音） | 谱面驱动 + 逐字换元音 + 咬字 あ/ら/は + 48 段 SVC 采样 | “跟着你唱的歌实时和声，还会分 あ/ら/は 咬字” |
| **跟唱判定 + 她会高兴** | YIN + 谱面、命中率、唱完给总结 | “你唱得准她就高兴” |
| **任意歌曲一首变曲包** | `pipeline.py` 一键导入（开发版/组件） | 这是**创作者向**卖点，别放进首发宣传 |
| **她的翻唱（音色转换）** | 整首 230 s SVC 音色转换 | “把原唱换成她的音色” —— 版权敏感，宣传要谨慎 |
| **桌面级存在感** | 透明置顶 + 点击穿透 + 拖拽 + 走路会真的走开 | 桌宠基本功，但要做到不打扰（点击穿透/锁定） |
| 轻量 | 不接云端 LLM（已决定不做）、不需要 GPU | “装上就能用，不联网也能唱” |

**不建议的卖点**：灯光/舞台（回退过）、LLM 对话（成本高、体验差）、语音识别（砍过）。
首发宣传如果打“AI 会聊天”，第一批用户会立刻拿对话质量来评价，而这不是这项目最强的地方。

## 三、发到哪（按投入产出排）

| 平台 | 适合 | 要注意 |
|---|---|---|
| **B 站 + 爱发电（国内）** | 主战场。桌宠 + 日系歌 + 二次元受众，视频传播快 | 曲包版权（自己的歌/翻唱）不能随包；用“演示视频 + 赞助版” |
| **itch.io** | 海外桌宠/小工具受众，零门槛、可 PWYW、无需签名 | 英文页；要 NSIS 安装包（**已经有了**：`release/伴唱桌宠 Setup 0.0.1.exe`，89.6 MB；没有代码签名，SmartScreen 会提示「未知发布者」） |
| **Booth（Pixiv）** | 日本同人市场，VRM/桌宠类目成熟，接受付费 | 需要日文说明 + 素材授权写清楚（VRM 已授权） |
| **Steam**（桌宠/壁纸类） | 最大曝光 | $100 上架费 + 审核；要稳定安装包、要有“不含侵权素材”的干净版；**建议放到 v0.2 之后** |
| **GitHub Releases** | 开发版/给会折腾的人 | 不需要打磨，先发这个最快 |

**建议节奏**：
1. **v0.1（已决定，2026-11-18）**：**GitHub Releases 发「开发预览」**——免费、只发源码 + 安装包，
   说明里写清「没有自带曲目、安装包不含导入」。物料已备：`README.md`（面向 GitHub 改写）、
   `docs/release-notes-0.0.1.md`、`release/SHA256SUMS.txt`、推送流程见 `docs/release.md` 九。
   B 站演示视频等有歌可演示时再发（现在她能做动作但唱不了，视频没内容）。
2. **v0.2**：爱发电 / itch.io 上赞助版（含自带 VRM + 更多动作）；同时把“导入歌曲”做成可选组件。
3. **v0.3+**：Booth（日文）；Steam 视反馈决定。

曲包一律**不随包**：发“曲包格式 + 导入教程”，让用户自己拿自己的歌。这样版权风险最低，
也顺便把“能导入任何歌”变成卖点。

## 四、轻量化方案（按性价比排）

### A. 立即可做（0.5 天，不改架构）

| 措施 | 收益 | 成本 |
|---|---|---|
| `electronLanguages: [zh-CN, ja, en-US]` 只留三套 locale | **−38 MB**（302.8 → 264.7） | 一行配置（已做） |
| NSIS 压缩（`compression: maximum`） | 安装包 **89.6 MB** | 一行配置（已做） |
| 去掉 `LICENSES.chromium.html`？ **不能**（法律要求），但它已在包内可接受 | — | — |
| `dist` 不拷 `public/`（已做） | −60 MB | 已完成 |
| sourcemap 不打包（已做） | −8 MB | 已完成 |
| 和声采样：只带音量最高的 24 段「あ」，え 作为可选下载 | −0.7 MB | 小 |

预计：免安装目录 **303 → 270 MB**，安装包 **~120 → ~95 MB**。
**实测（2026-11-18）**：264.7 MB / 89.6 MB —— 两项都做完了。

### B. 结构优化（1–2 天）

| 措施 | 收益 | 说明 |
|---|---|---|
| **拆「核心包 / 创作组件」** | 安装包 ~95 MB，创作组件单独 2.9 GB 按需下 | 已有 `docs/release.md` 三的 C 方案；要做的是下载器（断点续传 + 校验） |
| 模型可选：核心包不带 VRM，首启让用户拖一个 `.vrm` 进来 | −14 MB | VRM 已授权，但“用什么模型”其实该让用户选 |
| `deps` 瘦身：three 只 import 需要的模块（tree-shaking 已部分生效） | −2~4 MB | 收益一般，别为此改架构 |

### C. 换运行时（3–5 天，收益最大）

Electron 的 180 MB 是体积天花板。**Tauri 2**（WebView2，Win10+ 自带）：
- 运行时 **~5–10 MB**，安装包有望 **40–60 MB**，内存从 ~200 MB 降到 ~80–120 MB。
- 我们的主进程很薄（窗口 / 托盘 / 菜单 / IPC / 文件读写 / 启动 python），**可迁移**；
- 代价：托盘/点击穿透/全局热键/`nudge-window` 这些要用 Rust 重写；`--remote-debugging-port` 那套验证脚本要换到 Tauri 的 inspector。
- **建议**：v0.2 之后再评估。先用 A + B 把包压到 100 MB 以内，已经比大多数 Electron 桌宠小。

### D. 运行时轻（用户能感觉到的“轻”）

| 现在 | 建议 |
|---|---|
| 48 段循环全部解码进内存（1.9 s × 48 × 44.1k ≈ **16 MB** 浮点） | 只解码“当前元音 + 目标附近 3 档”，切歌/切元音时懒加载（内存 −12 MB，启动快） |
| 每 60 fps 更新和声参数 | 和声参数按 30 ms 节流（CPU 峰值降一半，听不出差别） |
| 动作裁剪常驻 | 待机时把非当前动作停掉 |
| 首启无曲包 | 引导“导入一首歌”或放一首 15 s 的原创演示曲（自制，无版权） |
